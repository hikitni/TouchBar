# HTTP Touch Bar v1.3 产品需求

> 状态：Draft — integration acceptance pending  
> Last verified：2026-09-08  
> 文档版本：v1.3.0  
> 日期：2026-09-08

## 1. 范围与目标

v1.3.0 在固定的三页 Touch Bar 体验上增加紧凑布局约定，并将原先面向 Codex 的今日 Token 面板泛化为本地 `ccusage` AI 用量面板。本文件定义面向产品、配置和集成的持久行为；它不替代历史版本说明。[`requirements-v1.2.md`](requirements-v1.2.md) 保留其发布时的历史语义，不重写为当前规范。

本版本继续只面向可信局域网中的 Mac Agent 与浏览器副屏。配对、权限边界、QQ 音乐控制策略和动作白名单不因本版本改变。

## 2. 页面与自适应布局

### 2.1 固定页面与导航

顶层页面固定为以下顺序：

1. 系统监控（`monitor`）
2. 控制（`control`）
3. 快捷方式（`shortcuts`）

底部标签导航必须预留页面内容空间，不能以覆盖层遮挡最后一个分组或操作项。

### 2.2 尺寸规则

- 视口宽度小于 `768px` 时，分组采用单列纵向布局。
- 横屏且可用高度不超过 `520px` 时，采用紧凑布局，优先保证页面标题、分组标题、核心状态和操作项可见。
- 其他尺寸可以使用由组列数和呈现提示决定的多列布局。

### 2.3 分组呈现提示

v2 组配置新增两个**可选**提示：

```json
{
  "presentation": "tiles",
  "span": "full"
}
```

- `presentation` 为 `"tiles"` 或 `"details"`，提示客户端使用指标磁贴或详情式呈现。
- `span` 为 `"auto"` 或 `"full"`，提示客户端按常规网格排布或占用全宽。
- 两个字段均为可选字段。未提供字段的既有 v2 配置以及经迁移的 v1 配置仍必须正常加载；客户端应采用兼容的默认样式。

详细的公共 TypeScript 接口、枚举和 `AiDailyUsage` 数据类型以 `packages/protocol/src/index.ts` 为准。

## 3. 默认配置

默认配置 `apps/agent/config/default.json` 与可分发示例 `config/touchbar.example.json` 必须内容一致。所有既有动作 ID、URL、Bundle ID、QQ 音乐快捷键和系统设置动作保持不变。

### 3.1 系统监控

分组顺序必须为：系统资源 → 设备与 Agent → 今日 AI 消费。

| 组 ID | 标题 | 默认提示 | 其他约束 |
|---|---|---|---|
| `system_resources` | 系统资源 | `tiles`、`full` | 保持 4 列；显示 CPU、内存、磁盘和电池。 |
| `device_agent` | 设备与 Agent | `details`、`full` | 保留设备、网络、运行时间和 Agent 统计；移除独立的 `device_time` 状态项，时间由 UI 标题区显示。 |
| `codex_today` | 今日 AI 消费 | `details`、`full` | 为兼容已有配置保留 ID；其 `tokens_today` 项标签改为“今日 AI 消费”。 |

`codex_today` 的说明必须明确：它汇总本机所有受 `ccusage` 支持的本地来源在今天的用量，每 10 分钟刷新，金额为 USD 估算，不等同于账单。

### 3.2 控制与快捷方式

- `system_controls` 使用 2 列；项目顺序必须为系统音量滑块、切换静音、立即息屏。音量滑块为首项并保持全宽渲染能力。
- `favorite_apps` 只有 QQ 音乐一个默认项，因此列数为 1；该项继续复用 `qqmusic_launch`。
- 系统资源保持 4 列。其余动作引用、URL、应用 Bundle ID 和系统设置语义不得因布局调整而改变。

## 4. AI 用量数据契约

### 4.1 数据来源与范围

Agent 调用已固定到 `20.0.20` 的本地 `ccusage` CLI。正常 `pnpm install` 会安装其包和可选的平台原生二进制；可执行命令及该二进制必须可用，AI 采集才能运行。Agent 不得以后台 `npx`、下载 `latest` 或重新安装的方式修复缺失依赖。

采集范围为 `ccusage` 支持的所有本地工具来源；调用使用 JSON 输出及按 Agent 的聚合数据，以来源和模型维度展示。日期为 Mac 本地时区的“今天”。货币固定 USD。

该统计不是：

- 账户或组织账单；
- API 全局用量；
- 其他设备、云端或任意未被 `ccusage` 读取的数据；
- RMB 报价、历史报表或手动价格编辑器。

### 4.2 统计与展示规则

- 日报总 Token 与输入、输出、缓存读取、缓存写入四个分项遵循 `ccusage` 口径；不得把日报、来源小计、模型明细相加，也不得在日报总 Token 上重复累加缓存。
- 缺少单价的数据必须标记为未知或部分可估，不能视为免费。
- 如果没有任何可汇总的已知价格，金额总额显示 `—`。
- 当上游没有提供调用次数或推理指标时，客户端不显示相应指标。
- Touch Bar Agent 仅解析 CLI 返回的汇总字段，不接收、传输或显示提示词、回复正文及会话路径。`ccusage` 在本机处理其日志，不能把该边界解释为底层工具从不读取含正文的文件。

公共状态接口 `AiDailyUsage` 是当前通用 AI 用量模型，包含日期、时区、币种、collector、collectorVersion、刷新状态、总量、模型和来源。它替代旧的可空 Codex 专属字段；状态采集必须只轮询此统一数据源，不能保留并行的旧 Codex 轮询造成重复采集。

### 4.3 生命周期、缓存与失败

1. 首次需要 AI 用量时异步启动采集，不阻塞控制页面或其他 Agent 功能。
2. 仅当有活动客户端时，最多每 600 秒刷新一次；同时请求必须 single-flight 合并为一次 CLI 调用。
3. 没有活动客户端时暂停周期采集；客户端重连只在缓存已过期时触发刷新。
4. 单次 `ccusage` CLI 调用的超时为 60 秒。
5. 调用失败时保留同一天的最近缓存，并将其标记为陈旧/错误；不得把旧缓存伪装成新数据。
6. Mac 本地日期跨越午夜时，丢弃旧日期缓存，不能将前一天数据展示为今天。
7. 当命令或平台二进制缺失时，AI 面板显示可理解的错误；配对、系统控制、QQ 音乐和其他 Agent 功能继续可用。

## 5. 操作反馈与权限

- 已成功的操作反馈显示 5 秒后消失。
- 失败反馈必须由用户关闭；新的操作不重播旧的成功或失败反馈。
- 本版本不自动触发 macOS 辅助功能授权提示。
- QQ 音乐继续检查应用与辅助功能权限、激活应用、发送已配置快捷键并保持前台；不改变现有策略。由于 QQ 音乐没有可读取的标准播放状态，快捷键投递成功仍只能标记为“已发送”，不得伪装为已验证。

## 6. 隐私与安全

浏览器只能执行服务端配置的动作 ID 和受约束的滑块值，不能提交任意 shell、AppleScript、URL、Bundle ID 或按键组合。

服务默认使用可信局域网的 plain HTTP。不得通过端口转发暴露到公网；公网访问需要 HTTPS、安全隧道或反向代理鉴权。AI 统计仅使用本地结构化汇总，不携带会话正文。

## 7. 验收标准

1. v1 与 v2 既有配置均可通过协议加载；省略 `presentation` 或 `span` 的配置保持兼容。
2. 默认配置与示例配置逐字一致，并通过共享协议校验。
3. 监控页默认组顺序、4 列系统资源、全宽提示、设备详情提示、去除 `device_time`、AI 组标题和兼容 ID 符合第 3 节。
4. 系统控制为两列，系统音量滑块是第一项；默认收藏应用为单列并复用既有 QQ 音乐启动动作。
5. 小于 `768px` 的纵向视口为单列；低高度横屏（可用高度不超过 `520px`）为紧凑布局；固定标签不遮挡内容。
6. AI 面板使用固定的本地 `ccusage` `20.0.20`、JSON 和按 Agent 数据，正确展示来源/模型、Mac 当天时区和 USD 估算边界。
7. `ccusage` 缺失、超时、上游指标或价格缺失、没有客户端、重连、跨午夜和调用失败均遵循第 4 节的可用性、缓存和错误语义。
8. 反馈 5 秒成功消失、失败可关闭且不重播；辅助功能提示和 QQ 音乐策略不发生自动化或意外变化。

## 8. 验证命令

配置范围的针对性检查：

```bash
pnpm --filter @touchbar/agent exec vitest run test/config.test.ts
```

完整类型检查、测试和构建由集成主线执行：

```bash
pnpm typecheck
pnpm test
pnpm build
```
