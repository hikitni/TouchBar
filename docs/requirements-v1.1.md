# HTTP Touch Bar v1.1 优化需求

- 文档版本：v1.1
- 日期：2026-09-07
- 状态：已实现

## 1. 目标

在首版局域网副屏基础上，聚焦“常用控制、明确反馈、轻量监控”：默认页面以 QQ 音乐和系统音量为主，所有界面中文化，并新增 Mac 与本地 Codex 使用状态监控。

## 2. 功能范围

### 2.1 操作结果

- 每次按钮或滑块操作均返回结构化 `ActionResult`。
- 浏览器展示“执行中、成功、失败”状态、结果信息和完成时间。
- 服务端非 2xx 动作结果仍由前端解析并展示，不再统一丢失为网络错误。
- 同一按钮执行期间禁用，防止重复触发。
- 原始 macOS 错误仅写入 Mac 本地 Agent 日志，不返回敏感诊断内容。

### 2.2 系统监控页面

每 3 秒通过已有 WebSocket 推送一次轻量状态；磁盘、电池、系统版本和 Codex Token 使用采用 15 秒缓存，避免频繁系统调用。

监控内容：

- CPU 使用率与 1 分钟负载
- 内存使用量、总量和占比
- 系统盘使用量、总量和占比
- 电池电量与充电状态（无电池设备显示未检测到）
- macOS/Agent 运行时间
- 主机名与优先局域网 IPv4 地址
- Agent 累计操作次数、当前 WebSocket 在线设备数
- 当日本地 Codex 最新会话的任务 Token、本轮 Token、上下文占比和周期配额占比

Codex 监控只读取 `~/.codex/sessions/YYYY/MM/DD` 最新 JSONL 文件尾部的 `token_count` 聚合事件，不读取或展示对话正文；未发现数据时显示不可用。Token 数量是用量统计，不是费用估算。

### 2.3 QQ 音乐与中文化

- 默认媒体目标改为 `/Applications/QQMusic.app`（Bundle ID `com.tencent.QQMusicMac`）。
- 上一首、播放/暂停、下一首通过固定的 macOS 媒体键事件发送。
- 默认页面移除截图、显示器休眠、浏览器启动器、BTT 示例等低频入口，但配置协议仍保留这些扩展能力。
- 默认保留 QQ 音乐、系统音量、切换静音、亮度和锁屏。
- 配对页、状态页、错误提示、确认提示和操作结果全部中文化。

### 2.4 性能与控制

- 音量滑块发送间隔由 90ms 调整为 140ms，并在松手时立即发送最终值。
- 服务端继续串行执行音量请求，避免 AppleScript 堆积。
- 音量与系统状态刷新分别合并并发请求。
- 慢速系统指标使用缓存；无 WebSocket 客户端时停止周期采集。
- 状态推送采用单个防重入定时任务，避免采集重叠。

## 3. 验收标准

1. QQ 音乐控制页可以发送上一首、播放/暂停、下一首指令。
2. 每个操作均显示执行中及最终成功/失败结果。
3. 系统监控页自动更新，且 Agent 无连接设备时不进行周期采集。
4. 可以显示本地 Codex Token 聚合数据；无数据时页面正常降级。
5. 页面所有用户可见的核心文案为中文。
6. `pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。
